# ADR-0001: How v0.1.0 differs from the master prompt's assumptions

- Status: accepted (items 7, 8, 9 and 10 need a human decision; see "Open questions")
- Date: 2026-09-30
- Phase/Step: 0 / 0.1

## Context

The v0.2.0/v0.3.0 master prompt describes MangaAR v0.1.0 generically. The audit
(`docs/AUDIT_v0.1.0.md`) found several concrete differences. OP-1 requires recording
them and adapting.

## Differences and decisions

| # | Prompt assumption | Reality in v0.1.0 | Decision |
|---|---|---|---|
| 1 | GUI framework unknown (PyQt/PySide or other) | Gradio 6 Blocks | Under rule P2.1 the Phase 2 default is the local FastAPI web app. Decided in the Phase 2 GUI ADR, only after the checkpoint. |
| 2 | Inputs may include PDF | No PDF input (images, folders, CBZ/ZIP only) | Nothing to preserve. PDF stays out of scope for v0.2.0 (logged in `docs/BACKLOG.md`). |
| 3 | Supported languages to be discovered | Source ja/ko/zh (+auto), target ar only | All preserved. English *source* support (Latin OCR route) is added in Phase 1, because Phase 2 consumes Phase 1 OCR on English pages. It is feature-flagged and off in the `legacy` profile. |
| 4 | Region types {dialogue, thought, narration, sfx, sign, credit} | {bubble, narration, free_text, sfx} | The typed `TextRegion` record uses the prompt's taxonomy. Legacy mapping: bubble→dialogue, narration→narration, free_text→sign, sfx→sfx. thought/credit need new classifiers (Phase 1.0). |
| 5 | Branch `release/0.2.0` | Session branch `claude/peaceful-meitner-4wcz28` is the only branch this session may push | Work happens on a local `release/0.2.0`. Commits are pushed with `git push origin release/0.2.0:claude/peaceful-meitner-4wcz28` until the human authorises pushing a remote `release/0.2.0`. |
| 6 | Tag `v0.1.0` may not exist | `v0.1.0` exists locally on `7ac6718` (the remote refuses tag pushes). Tags `phase-0-complete`…`phase-7-complete` exist from the v0.1.0 build | `v0.1.0` is the baseline and is never moved. Gate tags use distinct names (`phase1-gate-candidate`, `phase1-gate-passed`). `audit_phase_order.py` only checks commits after `v0.1.0`, because v0.1.0 history predates the trailer convention. |
| 7 | Mandatory models (NLLB-200, GGUF LLMs, sentence-transformers) are obtainable | huggingface.co is blocked on this host (HTTP 000) | Escalated. The provider code, schemas and tests can be built with fakes, but G-TR cannot be *measured* here without the weights. The human must supply the models (a local path or an allow-listed mirror), approve a deviation ADR, or waive. |
| 8 | LPIPS computable | The LPIPS backbones come from download.pytorch.org (blocked) | Escalated. SSIM and PSNR are computed; LPIPS needs the backbone weights, which must be supplied or waived. |
| 9 | v0.1.0 translation is a meaningful baseline | v0.1.0's online providers and local MT weights are blocked here; only the translation memory works, so the baseline would output nothing for unseen text | Escalated. Proposed: a TM-free baseline run on a host with network access, or a human waiver defining the G-TR baseline. A gate comparing against an empty baseline would be meaningless (PD-3). |
| 10 | Real gold data exists or can be requested | None in the repository | Requested once (consolidated request). Meanwhile, synthetic data only, with the SYNTHETIC-ONLY banner. |
| 11 | CI exists | No CI, no pre-commit, no pip-audit | Added in Phase 0.5 (a GitHub Actions workflow file plus `.pre-commit-config.yaml`). CI cannot be executed from this host; the workflow's commands are run locally and logged in the ledger. |
| 12 | `docs/LICENSES.md` | v0.1.0 generates `docs/THIRD_PARTY_LICENSES.md` | `docs/LICENSES.md` becomes the mandatory register (G-LIC-1): it is generated by `scripts/license_report.py` and extended with datasets. `THIRD_PARTY_LICENSES.md` stays as a pointer for backward compatibility. |

## Consequences
- Phase 0 and most of Phase 1 can proceed on this host: OCR/detection, inpainting,
  typesetting, harness and governance.
- Gate criteria that depend on blocked assets (G-TR-1 and parts of G-TR-3 need
  translation models; the LPIPS part of G-INP-2) cannot pass here until the human
  resolves items 7–9. The gate will report them as FAIL or NOT-MEASURABLE rather than
  pass by construction.

## Open questions (sent in the consolidated request)
1. Push authorisation for a remote `release/0.2.0` branch.
2. Supply or waive NLLB-200 / GGUF / embedding models (item 7) and the LPIPS backbone
   (item 8).
3. Definition of the G-TR baseline (item 9).
4. Whether English as a *target* language is in scope for v0.2.0. The prompt's English
   typesetting requirements (Wild Words, pyphen) are ambiguous, since the product's
   target is Arabic.
